git config user.email "jackbashroot-boop@users.noreply.github.com"

--- B) Publish the release the updater reads (5 files) ---------------
cd $DL
unzip -o Aegis-Release-v1.2.24-FILES.zip -d release-v1.2.24
ls release-v1.2.24
gh release create v1.2.24 release-v1.2.24/* -R jackbashroot-boop/AEGIS-Desktop --title "AEGIS Suite v1.2.24" --notes "Companion 1.8.12 + PHOENIX 0.12.15: Cardputer safe-mode loop fixed, desktop network list stable."

--- C) From NEXT release on, GitHub can build it for you -------------
The repo now carries .github/workflows/release.yml + ci/release_build.py.
After A) is pushed once:
  git tag v1.2.24
  git push origin v1.2.24
GitHub Actions builds Companion + PHOENIX and publishes the Release.
(First tag push is the workflow's real-world test - watch the Actions tab.
The Companion's Settings > Publish staged PHOENIX button also still works
for firmware-only drops onto the latest release, using your own gh login.)
